Type `/` in the Grok Build prompt to open the fuzzy command menu. As you type, the list filters in real time. Press `Tab` or `Enter` to accept the highlighted command and run it immediately.

Commands come from three sources: **shell builtins** (handled by the agent backend), **pager builtins** (handled by the TUI frontend), and **enabled skills** with `user-invocable: true`. All three appear in the same menu. If a skill shares a name with a built-in, the built-in keeps the bare name and the skill is available under a qualified path — the menu badges both so the collision is visible.

## Session Management

### `/new`
Start a fresh session and clear the current conversation. Alias: `/clear`.

### `/resume`
Open the session picker to reload a previous session from disk.

### `/dashboard`
Open the **Agent Dashboard** — a live roster of top-level sessions with peek, reply, dispatch, pin, rename, stop, and attach actions. Aliases: `/agents-dashboard`, `/sessions`. Hidden in minimal mode; disable with `GROK_AGENT_DASHBOARD=0` or `[dashboard].enabled = false`.

### `/compact [context]`
Compress conversation history to reclaim context-window space. Pass an optional note to tell Grok what to preserve:

```
/compact
/compact keep the auth implementation details
```

Grok also auto-compacts once the context window hits 85% (tunable with `[session] auto_compact_threshold_percent`).

### `/context`
Show how the context window is being used — a category breakdown covering the system prompt, messages, reasoning overhead, free space, tool definitions, skills listing, and MCP server announcements with estimated token cost.

### `/session-info`
Show session details: auth method, model, turn count, and context usage. Aliases: `/status`, `/info`. Press `c` to copy the session ID or `y` to copy the whole block.

### `/fork`
Branch the current session into a new agent, preserving history up to this point.

### `/rewind`
Roll the conversation back to an earlier turn and discard everything after it. Alias: `/undo`.

### `/edit-prompt`
In minimal mode, open an external editor for an empty composer. Grok resolves `$VISUAL`, then `$EDITOR`, then `vi`. Saving replaces the draft without sending it; saving an empty file clears it. Hidden outside minimal mode.

```
/edit-prompt
```

### `/copy`
Copy the most recent response to the clipboard. Pass a number to copy the *N*th-latest response, or a file path to write to a file instead of the clipboard (useful over SSH):

```
/copy
/copy 2
/copy out.txt
/copy 2 ~/exports/last-reply.md
```

Every copy is also written to a backup file at `~/.grok/last-copy.txt` (or `GROK_COPY_FILE` if set).

### `/export`
Export the full conversation to a file or the clipboard.

### `/quit`
Quit the application. Alias: `/exit`.

### `/home`
Leave the current session and return to the welcome screen. Alias: `/welcome`.

### `/delete`
Delete the current session's history (confirms first). Stops any running turn, background tasks, and subagents before wiping history, then returns to the welcome screen. To delete a session you are not currently in, open `/resume` or the session list and press `d` then `y`.

### `/rename`
Rename the current session. Alias: `/title`.

```
/rename new session title
/rename --auto
```

`--auto` unpins a manual title and lets auto-titling resume (Build sessions only). It must be the only argument.

## Model and Mode

### `/model <name>`
Switch models. Accepts a model ID or display name (case-insensitive); for reasoning models you can also pass an effort level as a second argument. Alias: `/m`.

```
/model grok-build
/model Grok Build
/model Reasoning X high
```

### `/effort <level>`
Set reasoning effort on the **current** model without reselecting it. Levels: `low`, `medium`, `high`, `xhigh`. Only applies when the active model supports reasoning effort.

```
/effort high
```

### `/always-approve` and `/auto`
Both are real toggles for permission mode — running the mode you are already in switches it back off:

| Command | When off | When already on |
|---------|----------|-----------------|
| `/always-approve` | Skip all permission prompts | Back to ask |
| `/auto` | Classifier approves safe tools (dangerous ones may still prompt) | Back to ask |

Running one while the other is active switches modes. You can also change mode with `Shift+Tab` (cycles Normal → Plan → Always-approve), `Ctrl+O`, or `/settings`.

### `/multiline`
Toggle multiline input. When on, `Enter` inserts a newline and `Shift+Enter` (or `Alt+Enter`) sends. Alias: `/ml`.

### `/history`
Open prompt-history search: fuzzy-search this session's prompts newest-first, then press `Enter` or `Tab` to drop a match into the prompt.

For quick recall, press `↑` on an empty prompt — the panel opens with your most recent prompt already filled in.

### `/compact-mode`
Toggle compact display — less padding and tighter spacing for denser output.

### `/vim-mode`
Toggle Vim-style scrollback navigation keys (`j`/`k`, `h`/`l`, `g`/`G`, `y`/`Y`, and so on). The setting persists to `[ui] vim_mode`. See [Keyboard Shortcuts](/keyboard-shortcuts) for the full reference.

### `/minimal` and `/fullscreen`
Reopen the current session in the other render mode. `/minimal` switches to scrollback-native mode; `/fullscreen` (alias `/full`) switches back to standard fullscreen. Both relaunch the pager on the same conversation for this session only — they do not modify `config.toml`. To make the mode persist across launches, use `/settings` → **Default screen mode** or set `[ui] screen_mode`.

### `/plan`
Enter plan mode.

```
/plan [description]
```

### `/view-plan`
Open a preview of the current saved plan. Aliases: `/show-plan`, `/plan-view`.

## Memory

`/flush`, `/dream`, and `/memory` require memory to be enabled via `GROK_MEMORY=1`, `[memory] enabled = true`, or managed remote settings. `/remember` is always available.

### `/memory`
Browse, view, and manage saved memories. Pass `on` or `off` to enable or disable memory. Alias: `/mem`.

```
/memory
/memory off
```

### `/flush`
Save the current session's knowledge to memory right now, triggering an LLM summary of the most important content. Useful before compaction or when you want to lock in context.

### `/dream`
Run memory consolidation — merge session logs into organized topics.

### `/remember`
Save a note to memory immediately, without waiting for an automatic summary.

```
/remember the staging deploy uses the eu-west cluster
```

## Hooks and Plugins

`/hooks`, `/plugins`, `/marketplace`, and `/skills` all open the same extensions modal, each starting on its respective tab.

### `/hooks`
Open the extensions modal on the **Hooks** tab. View loaded hooks, add or remove custom ones, and toggle them individually.

### `/plugins`
Open the extensions modal on the **Plugins** tab. View installed plugins, install new ones, and manage trust.

### `/marketplace`
Open the extensions modal on the **Marketplace** tab. Browse and install plugins.

### `/skills`
Open the extensions modal on the **Skills** tab. View all installed skills.

## Media Generation

### `/imagine <description>`
Generate an image from a text description.

```
/imagine a golden sunset over a calm ocean with silhouetted palm trees
```

### `/imagine-video <description>`
Generate a video from a text (or image) description. Grok plans shots, generates source images, and animates them.

```
/imagine-video a cat playing piano in a jazz club
```

## Scheduling

### `/loop [interval] <prompt>`
Run a prompt on a recurring interval. Specify the interval as `30m`, `1 hour`, or `every 2 days`; omit it and Grok will ask.

```
/loop 30m check deploy status
/loop check deploy status every hour
```

Intervals: `Ns` (seconds, minimum 60), `Nm` (minutes), `Nh` (hours), `Nd` (days). Recurring tasks expire after 7 days; cancel one with `scheduler_delete` using the job ID reported at creation.

## Workflows and Goals

### `/goal`
Set, manage, or check an autonomous goal. Grok works across rounds and only marks a goal complete after an independent evidence review confirms the claim.

```
/goal Migrate the auth module to the new API
/goal status
/goal pause
/goal resume
/goal clear
```

Arguments: `<objective> [--budget <tokens>]`, or one of `status`, `pause`, `resume`, `clear`.

### `/deep-research <query>`
Kick off a background research workflow. Grok plans a bounded set of questions, gathers structured claims with source evidence, cross-checks each claim, and renders only those that survive verification. Returns immediately — follow progress in `/workflows`.

```
/deep-research Compare the migration risks of PostgreSQL 17 and MySQL 9
```

### `/workflow`
Launch a saved workflow, or manage a running one by its display name as shown in `/workflows`.

```
/workflow review-changes {"target":"origin/main...HEAD"}
/workflow pause review-changes
/workflow resume review-changes
/workflow stop review-changes-2
/workflow save review-changes
```

Project workflows live in `.grok/workflows/*.rhai`; user workflows in `~/.grok/workflows/*.rhai`.

### `/workflows`
Open the live workflows **run** dashboard — active and retained runs, not a catalog of saved definitions. Each row shows the display name, phase, agent roster, progress, and result.

## Other

### `/theme`
Switch the color theme. Alias: `/t`. See [Theming](/theming) for available themes and configuration.

### `/feedback [message]`
Report an issue or send feedback. A message sends immediately; without one, a pane opens for a longer report (`Enter` sends, `Esc` discards).

```
/feedback
/feedback Something isn't working correctly
```

### `/btw`
Send an aside to the agent without interrupting the current task. The side question and its answer are not part of the main turn.

```
/btw also check the error handling
```

### `/mcps`
Open the MCP servers management modal.

### `/doctor`
Check the current session for terminal, clipboard, color, input, notification, and sandbox issues. Shows findings and resolution steps. Run `/doctor fix` to list available automatic fixes. Aliases: `/terminal-setup`, `/terminal-check`, `/terminal-info`.

### `/release-notes`
View release notes for the current version. Alias: `/changelog`.

### `/docs`
Browse the built-in How-to Guides, open the online Build docs, or jump to a guide by title.

```
/docs
/docs web
/docs Getting Started
```

Aliases: `/howto`, `/guides`.

### `/tutorial`
Open the onboarding tutorial — a short list of topics covering first prompts, attaching context, navigation, slash commands, worktrees, plan mode, customization, and switching from another agent tool. Nothing auto-shows; this command (or the palette) is the only way in.

Aliases: `/tour`, `/onboarding`.

### `/import-claude`
Open the Claude import modal to bring over `~/.claude` settings: permissions, environment variables, MCP servers, hooks, and paths.

## Skills as Slash Commands

Any enabled skill with `user-invocable: true` in its `SKILL.md` frontmatter appears in the slash command menu. Turn a skill off via `/skills` to stop it being advertised. A skill at `~/.grok/skills/commit/SKILL.md` runs as:

```
/commit fix typo in README
```

Skills from plugins work the same way.

<Tip>
When two skills share the same name across scopes, qualify the invocation to disambiguate:

```
/local:commit      # Project-scoped skill (from .grok/skills/)
/user:commit       # User-scoped skill (from ~/.grok/skills/)
```

Built-in commands always win the bare name. Both the built-in (tagged `built-in`) and the skill (tagged `skill · local` or `skill · plugin-name`) appear in the slash menu so you can see the collision.
</Tip>

## Autocomplete

The slash menu supports **fuzzy search**: start typing after `/` to filter. Each entry shows the command name, a description, an argument hint (when applicable), and its source (`builtin`, skill scope, or plugin name). Press `Tab` or `Enter` to accept the highlighted command.
