Grok uses SpaceXAI-hosted models by default. Custom endpoints let you connect alternative providers, self-hosted models, and enterprise gateways — giving your team full control over model selection while keeping the same Grok workflow.

## Default Models

New sessions start with `grok-4.5`. No configuration is required for SpaceXAI models. Authenticate with `grok login` or set the `XAI_API_KEY` environment variable, then start a session.

List all available models (built-in and custom):

```bash
grok models
```

---

## Switching Models

### At Launch

```bash
grok -p "Hello" -m grok-build
```

### In a Session

```text
/model grok-build
```

Or use the short alias:

```text
/m grok-build
```

### In Config (Persistent Default)

```toml
# ~/.grok/config.toml
[models]
default = "grok-4.5"
```

### Model Picker

Press `Ctrl+M` from the scrollback pane to open the interactive model picker. It lists all available models — both built-in and custom — and lets you switch with a single keystroke. If the prompt is focused, `Ctrl+M` toggles multiline input instead; use `/model` in that case.

## Custom Model Configuration

Add custom model endpoints in `~/.grok/config.toml` under `[model.<name>]` sections. The name you choose becomes the identifier you pass to `-m` or `/model`.

```toml
[model.my-model]
model       = "model-id"                       # Model identifier sent to the API
base_url    = "https://api.example.com/v1"     # OpenAI-compatible endpoint
name        = "Display Name"                   # Shown in the model picker
description = "Model description"             # Optional
api_key     = "sk-..."                         # API key for this provider (optional)
env_key     = "MY_PROVIDER_API_KEY"            # Env var holding the API key (optional)
api_backend = "chat_completions"               # "chat_completions", "responses", or "messages"
temperature             = 0.7
top_p                   = 0.95
max_completion_tokens   = 8192
context_window          = 128000
extra_headers           = { "x-api-key" = "sk-..." }   # Extra request headers (optional)
query_params            = { api-version = "2026-07-22" } # Query params appended to every request (optional)
env_http_headers        = { "X-Tenant" = "TENANT_TOKEN" } # Headers from env vars (optional)
```

### Ollama (Local)

Run models locally with [Ollama](https://ollama.ai):

```toml
[model.ollama-codellama]
model    = "codellama"
base_url = "http://localhost:11434/v1"
name     = "CodeLlama (Ollama)"
```

Make sure Ollama is running (`ollama serve`) and the model is pulled (`ollama pull codellama`).

### Anthropic / Claude

```toml
[model.claude-opus]
model          = "claude-opus-4-6"
base_url       = "https://api.anthropic.com/v1"
name           = "Claude Opus 4.6"
api_backend    = "messages"
context_window = 200000
extra_headers  = { "x-api-key" = "sk-ant-...", "anthropic-version" = "2023-06-01" }
```

The `messages` backend uses the Anthropic Messages protocol. Anthropic authenticates with an `x-api-key` header rather than `Authorization: Bearer`, so pass your key through `extra_headers`.

### OpenAI-Compatible

```toml
[model.gpt-4o]
model    = "gpt-4o"
base_url = "https://api.openai.com/v1"
name     = "GPT-4o"
env_key  = "OPENAI_API_KEY"
```

`api_backend` defaults to `"chat_completions"`, so you do not need to set it explicitly for standard OpenAI-compatible endpoints.

### OpenAI (Responses API)

If your provider supports the newer Responses API:

```toml
[model.gpt-4o-responses]
model      = "gpt-4o"
base_url   = "https://api.openai.com/v1"
name       = "GPT-4o (Responses)"
api_backend = "responses"
env_key    = "OPENAI_API_KEY"
```

### Together AI

```toml
[model.together-mixtral]
model    = "mistralai/Mixtral-8x7B-Instruct-v0.1"
base_url = "https://api.together.xyz/v1"
name     = "Mixtral 8x7B"
env_key  = "TOGETHER_API_KEY"
```

## API Backends

| Backend | Protocol | When to Use |
|---------|----------|-------------|
| `chat_completions` | OpenAI Chat Completions (`/v1/chat/completions`) | **Default.** Use for OpenAI, Ollama, Together AI, and most OpenAI-compatible providers. |
| `responses` | OpenAI Responses (`/v1/responses`) | Use for providers that support the newer Responses API. |
| `messages` | Anthropic Messages (`/v1/messages`) | Use for Anthropic directly; requires `x-api-key` in `extra_headers`. |

## Credential Resolution

Grok resolves the API key for each model in this order:

1. **`api_key`** field in the model's `[model.<name>]` config block
2. **`env_key`** — a single environment variable name or an array of names; the first set, non-empty value wins (e.g. `env_key = ["ANTHROPIC_AUTH_TOKEN", "LC_ANTHROPIC_AUTH_TOKEN"]` for SSH `LC_*` forwarding)
3. **Session token** from `grok login`, for a model with no `api_key` or `env_key` of its own
4. **`XAI_API_KEY`** environment variable (global fallback; `GROK_CODE_XAI_API_KEY` is also accepted for backward compatibility)

## Enterprise Deployment

Use `GROK_MODELS_BASE_URL` to point all inference at a corporate gateway. The following environment variables are available:

| Variable | Required | Description |
|----------|----------|-------------|
| `GROK_MODELS_BASE_URL` | Yes | Base URL for inference. Grok fetches the model list from `{base_url}/models`. |
| `XAI_API_KEY` | Yes | API key sent as `Authorization: Bearer`. Grok also accepts `GROK_CODE_XAI_API_KEY`. |
| `GROK_MODELS_LIST_URL` | No | Override the model-list URL when it differs from `{base_url}/models`. |

```bash
export GROK_MODELS_BASE_URL="https://api.acme.com/v1"
export XAI_API_KEY="xai-..."
grok
```

Or configure it in `config.toml` alongside per-model overrides:

```toml
[endpoints]
models_base_url = "https://api.acme.com/v1"

[model.company-grok]
model          = "grok-build"
name           = "Grok Build Latest (Proxy)"
context_window = 128000
```

A complete enterprise configuration example:

```toml
[cli]
auto_update = false

[auth]
auth_provider_command = "/usr/local/bin/my-company-auth-provider"
auth_provider_label   = "Acme Corp"
auth_token_ttl        = 3600

[models]
default = "company-grok"

[model.company-grok]
model          = "grok-build"
base_url       = "https://grok-proxy.acme.com/"
name           = "Grok Build Latest (Proxy)"
context_window = 128000

[features]
telemetry = false
```

## Effort Levels

Switch the model's reasoning effort during a session:

```text
/effort low
/effort medium
/effort high
```

You can also set per-model effort defaults in config:

```toml
[models]
default_reasoning_effort = "medium"
```

## Overriding Built-in Models

Override specific fields of a built-in model without redefining everything. Unspecified fields inherit from the default configuration:

```toml
# Override only the API key for a default model
[model.grok-build]
api_key = "my-api-key"

# Override temperature and API key
[model.grok-build]
temperature = 0.5
api_key     = "sk-custom"
```

Priority order when Grok resolves a model's configuration:

1. Your `[model.*]` config — highest priority
2. Prefetched models from remote `/v1/models`
3. Hardcoded defaults — lowest priority
